# 네이버 블로그 글 작성 (naver-blog-writer)

네이버 블로그는 두 개의 다른 게임이 동시에 돌아간다. **홈판(홈피드)** 은 검색 없이 앱 홈에서 추천되는 지면이라 감정·반전·궁금증이 클릭을 만들고, **검색/AI 브리핑** 은 결론 선행·구조화·1인칭 경험이 인용을 만든다. 같은 소재라도 두 모드의 제목·첫 문장·구조가 정반대이므로, 이 스킬은 먼저 모드를 정한 뒤 그 모드의 규칙만 적용한다.

모든 설명과 글은 한글. 이미지 프롬프트는 영어, 파일명은 영문 슬러그를 사용한다.

## 0. Claude 환경에서의 작업 원칙

- 작업 파일은 `/home/claude/blog/<slug>/`에서 만들고, 최종 전달물은 `/mnt/user-data/outputs/`로 복사한 뒤 `present_files`로 보여준다. 파일을 만들어 놓고 present 하지 않으면 사용자는 볼 수 없다.
- **이미지는 이 스킬이 생성하지 않는다.** 사용자가 GPT Image 또는 나노바나나2(Gemini 이미지)에 직접 넣을 **프롬프트만** 제공한다. 글 한 편당 **최대 3장**(썸네일 1 + 본문 2). 더 요청해도 3개에서 멈추고 "이 스킬은 3장까지만 잡습니다"라고 알린다. 프롬프트 규격은 [제작 절차](references/production_workflow.md)의 "이미지 프롬프트" 절을 따른다.
- 연결된 이미지 생성 MCP(Higgsfield 등)가 있어도 호출하지 않는다. 사용자가 명시적으로 "여기서 생성해줘"라고 할 때만 별도 확인 후 사용한다.
- HTML·ZIP은 `bash_tool`/`create_file`로 직접 만든다. 이미지가 없으므로 HTML은 **자리표시 방식**(예정 파일명 `01-thumbnail.png` 등)으로 만들고, 사용자가 생성한 이미지를 같은 파일명으로 저장하면 그대로 보이도록 상대 경로 `<img>`를 함께 넣는다.
- 글이 1,500자를 넘으면 `.md` 파일로 저장해 전달하고, 대화에는 제목·모드·리스크 요약만 남긴다.

## 요청 범위와 후속 작업

- 대화에서 정한 소재·운영자 감상·모드·제목·최신 본문을 이어받는다. 이미 받은 입력을 다시 묻거나 선택한 제목을 다시 고르게 하지 않는다.
- 기본 제작 흐름: 새 블로그 콘텐츠 제작은 글 → 이미지 프롬프트 3개(파일명·삽입 위치 지정) → HTML 2종(자리표시용·이미지 연결용) → 태그 → 전체 ZIP까지 완료한다. 기사 링크로 해설 블로그를 요청해도 같은 흐름을 적용하며 원고만 전달하고 끝내지 않는다.
- `글만`, `제목만`, `태그만`, `프롬프트만`, `이미지 프롬프트 없이` 등 범위를 제한한 요청은 그 부분만 처리한다. 후속 수정에서는 기존 결과를 재사용한다. 전체 제작 선호가 이미지 생성 도구 호출이나 실제 발행을 허용하는 것은 아니다.
- 새 콘텐츠 제작 또는 프롬프트 작성·번호 변경·HTML 변환 요청 시 [제작 절차](references/production_workflow.md)를 읽는다. 기존 프롬프트·파일명과 최신 본문을 재사용한다.
- 기사 링크·사건 해설 요청은 [기사 해설 원칙](references/news_commentary.md)을 읽는다. 링크는 `web_fetch`로 원문을 확인한 뒤 사실·분석·가상 예시를 구분한다.
- HTML 본문 마지막에는 `#태그1 #태그2` 형식의 해시태그 영역을 넣는다. 별도 태그 응답·tags.txt는 아래의 쉼표 형식을 사용한다.
- 태그만 요청하면 `#` 없이 쉼표와 공백으로 구분한 한 줄만 반환한다. 번호·제목·설명·코드블록은 붙이지 않는다. 명시한 다른 형식이 있으면 그것을 따른다.

## 2. 입력 수집

필요한 것은 세 가지뿐이다. 없으면 만들지 말고 묻는다.

1. **소재**: 뉴스 캡처·링크·유튜브 요약·본인 경험·한 줄 메모 중 하나
2. **운영자 감상 한 줄**: "나는 ○○인데 이 소식 보고 △△ 생각이 들었다" — 이 문장이 AI 글과 사람 글을 가르는 핵심이다. 개인 경험 중심 홈판형은 필수, 검색형은 권장. 기사·사건 해설은 운영자 감상이 없어도 중립적 분석으로 진행하며 감상 입력을 요구하거나 1인칭 경험을 창작하지 않는다. 없으면 "이 소재에 대한 본인 생각을 한 줄만 주세요"라고 묻는다
3. **카테고리·독자**: 프로젝트 지침·메모리·대화에 있으면 그것을 쓰고, 없으면 소재로 추정해 명시한다

이미 프로젝트나 메모리에 운영자 정보(카테고리·톤·금지 주제)가 있으면 그것이 우선이다.

## 3. 작성 절차

### 3-1. 제목 5안과 선택

- 홈판형: `장면 → 반전 → 궁금증` 3단 구조, 서로 다른 패턴 5개(반전·숫자·경고·인생장면·감추기), 각 제목 뒤 `(감정: ○○+△△ / 패턴: □□)` 표기, 추천 1개와 이유
- 검색형: `메인키워드 + 서브키워드 + 후킹문구`, 각 제목 뒤 `(메인: ○○ / 서브: △△)` 표기, 추천 1개
- 제목 다음에 **5문항 체크 결과**를 표로 붙인다 (참조 파일의 체크리스트). 4개 이상 ✔인 것만 추천 대상
- 사용자가 "1번 앞 + 3번 뒤"처럼 짜깁기를 요청하면 합쳐서 20자 내외로 다듬는다

기본은 제목 5안과 추천 이유를 보여주고 선택 후 본문을 쓴다. 사용자가 번호(예: `1`)를 고르면 해당 제목을 그대로 사용한다. "추천대로", "알아서 끝까지" 등 선택을 위임했다면 추천 제목으로 바로 진행한다. 제목을 직접 주었거나 이미 선택했다면 5안을 건너뛴다.

기사 링크로 완성 블로그를 요청한 경우에는 사실에 맞는 해설 제목을 정해 제작을 이어간다. 이후 홈판용 제목을 따로 요청하면 현재 본문에 맞는 후보 5개와 추천 이유를 제공한다. 후보를 제시한 것만으로 HTML 제목을 변경하지 않으며, 사용자가 선택·적용을 요청하면 HTML의 문서 제목·본문 제목·원고·ZIP을 함께 갱신한다.

다른 게시물과 실제로 비교하지 않았다면 차별성 항목은 `미확인`으로 표시한다. `web_search`로 실제 상위 제목을 확인한 경우에만 ✔를 준다. 검색·비교를 하지 않고 확인 표시나 경쟁력 점수를 만들지 않는다.

### 3-2. 본문

공통 규칙 (두 모드 모두):
- "안녕하세요", "오늘은 ~에 대해 알아보겠습니다" 절대 금지. 첫 문장은 사건 한가운데(홈판형) 또는 결론 수치(검색형)로 시작
- 운영자 감상을 본문에 녹인다. 1인칭 문장은 제공된 경험·감상 범위에서 구성하며 사용 도구·기간·성과·실패 사례를 지어내지 않는다. 문장 수를 맞추려고 경험을 추가하지 않는다.
- 뉴스 소재는 문장을 옮기지 않고 사실만 재서술, 하단에 `출처: 매체명, 날짜`
- 과장어(충격·경악·역대급·소름) 0개, 효능·수익·치료·예방 단정 0개
- 같은 접속사 2회 이상 반복 금지, "~할 수 있습니다" 3회 이상 금지, 마지막 문단은 정리가 아니라 독자에게 던지는 질문 하나
- 모바일 가독성: 한 문장 한 줄, 문단 사이 빈 줄
- 본문 끝 **자주 묻는 질문 3개** (`**Q. …**` / A.)

모드별 스펙:

| | 홈판형 | 검색/AEO형 |
|---|---|---|
| 분량 | 1,400~1,600자 | 1,800~2,500자 |
| 첫 문장 | 사건·장면 진입 | 첫 150자 안에 결론 수치 + 메인키워드 |
| 구조 | 인용구 5개 (`## ` 접두, 20자 이내, 다음 단락을 읽고 싶게) | H2 소제목 3~5개 (`## ` 접두), 각 소제목 단락은 자기완결형 |
| 감춘 것 | 첫 인용구 직후 반드시 공개 | 해당 없음 |
| 키워드 | 자연 배치 | 첫 100자 1회, 밀도 1.5~3%, 기계적 반복 5회 이상 금지 |
| 강조 | `**문장**` 3~5곳 | `**문장**` 3~5곳 |
| 이미지 자리 | 썸네일 1 + 본문 2 (가장 중요한 인용구 2곳 아래) | 썸네일 1 + 본문 2 (핵심 소제목 2곳 아래) |
| 마무리 | 질문형 | 질문형 + "함께 보면 좋은 글" 내부링크 자리 2개 `[내부링크: 관련 글 제목]` |

### 3-3. 본문 뒤에 붙이는 것

1. 핵심 키워드 3개 + 발행용 태그 8개. 태그는 `#` 없이 쉼표와 공백으로 구분한 한 줄로 출력한다(예: `AI업무자동화, 업무자동화, AI활용`). 별도 태그 목록은 본문 중간에 넣지 않는다. HTML 맨 아래에는 같은 태그에 `#`를 붙인 영역을 추가한다.
2. 이미지 프롬프트 **최대 3개**(GPT Image·나노바나나2 공용): 썸네일 1개 + 본문용 2개. 본문용은 글에서 가장 이미지가 필요한 인용구/소제목 2곳을 고르고, 어느 섹션 아래에 들어가는지와 예정 파일명(`01-thumbnail.png`…)을 표시한다. 영어 자연어 문장형, 16:9, **이미지 안 글자 없음(no text, no letters, no watermark), 실존 인물의 외모·닮은꼴 재현 없음**, 유명인 이슈는 실존 인물과 닮지 않은 가상 인물로 기사 맥락을 표현한다([제작 절차](references/production_workflow.md)의 유명인 이미지 기준). 3장의 화풍·조명·색감을 한 줄 "시리즈 스타일"로 먼저 정하고 세 프롬프트에 동일하게 넣는다. 각 프롬프트 끝에 한글 한 줄 설명. 한글 텍스트는 AI 이미지에서 깨지므로 글자는 스마트에디터에서 얹는다
3. **법적 리스크 점검표**: `references/legal_check.md`의 6개 항목을 본문에 대조해 `해당 없음 / 수정함(문장) / 사용자 확인 필요` 로 표시. 연예인·건강·금융·협찬 소재는 이 표를 생략하지 않는다
4. 발행 체크 5줄 (붙여넣기 방법 포함): 스마트에디터 붙여넣기는 `references/editor_paste_guide.md` 절차를 요약해 준다

## 4. 출력 형식

일반 글 작성은 `assets/post_template.md`를 따른다. 새 콘텐츠의 최종 전달물은 원고·이미지 프롬프트(최대 3개, prompts.md)·HTML 2종·태그·전체 ZIP이다. 후속 요청은 해당 결과만 제공한다. 순서: 모드·판단 근거 → 제목 5안+체크표 → (선택 후) 본문 → 키워드·해시태그 → 이미지 프롬프트 → 법적 점검 → 발행 체크. 일반 글은 마크다운 표시(`## `, `**`)를 유지한다. HTML 요청 시 이 표기를 실제 제목·강조 태그로 변환하며, 이미지 자리를 번호와 파일명으로 표시한다.

## 5. 하지 않는 것

- 발행·서로이웃·공감·댓글을 대신하지 않는다 (자동화는 네이버 운영정책 제재 대상이며 사람 개입 흔적이 노출 자산이다). Chrome 브라우저 도구가 있어도 네이버 발행 버튼을 대신 누르지 않는다
- 타인의 기사 사진을 재사용하거나 유명인의 외모·닮은꼴을 재현하지 않는다. 유명인 이슈에는 맥락에 맞는 가상 인물을 활용하며, 이를 모든 인물·얼굴 금지로 해석하지 않는다
- 이미지를 직접 생성하지 않고, 프롬프트도 4개 이상 만들지 않는다
- 하루 3편 넘는 대량 생산을 요청받으면 어뷰징 위험을 한 줄 알리고 3편 단위로 끊는다
- 조회수·수익을 보장하는 표현을 쓰지 않는다. 홈피드 노출은 네이버가 결정하며 재현 공식은 없다

## 6. 예시

**입력**: "77세 배우가 손녀한테 결혼할 때 집이랑 차 사달라는 말을 들었다는 기사. 나도 아들딸 있는데 이러면 큰일이다. 홈판용으로."
**출력 흐름**: 홈판형 판정 → 제목 5안 (예: 「집하고 차 다 해주세요 — 손녀 요구에 당황한 77세 배우, 내 아들딸도 이 말 하면 어쩌지?」 감정: 놀람+공감 / 패턴: 감추기→공개형) → 체크표 → 사용자 "5번" → 1,500자 본문(첫 문장: "처음에는 웃었습니다.") + 인용구 5개 + FAQ 3개 → 해시태그 → 이미지 프롬프트 3개(썸네일: 집 열쇠·차 키·예물상자 / 본문 2: 인용구 1·4 아래, 얼굴 없음) → 법적 점검(초상권: 얼굴 이미지 없음 ✔, 명예훼손: 보도 사실 범위 ✔, 사진: 기사 사진 미사용 ✔) → 발행 체크 → prompts.md(3개) → HTML 2종 → ZIP → present_files

## 7. 후속 요청 예시

- `1` → 앞서 제시한 1번 제목으로 본문 작성.
- `이미지 프롬프트 뽑아줘` / `나노바나나용으로` → 썸네일·본문 1·본문 2 순으로 최대 3개, `01`부터 파일명·삽입 위치 지정, prompts.md로 제공. "이미지 만들어줘"라고 해도 생성하지 않고 프롬프트를 준다(도구 호출은 명시 요청 시에만).
- `파일 이름 순서 바꿔줘` → 프롬프트 번호·파일명만 변경, HTML·prompts.md·ZIP의 참조도 동기화.
- `가독성 높은 HTML로, 이미지 자리도 표시해줘` → 현재 글을 모바일 HTML로 변환, 기존 이미지 번호·파일명을 삽입 위치에 표시.
- `해시태그 한 줄로 줘` → `AI업무자동화, 업무자동화, AI활용` 형식만 반환.
- `이 기사를 사건 해설 블로그로 작성해줘` → `web_fetch`로 원문 확인 → 독립적인 해설 → 이미지 프롬프트 최대 3개 → HTML 2종과 ZIP까지 완료.
- `HTML 본문 마지막에 # 포함 태그 추가` → HTML 2종의 태그 영역을 추가 또는 갱신하고 ZIP 동기화. 별도 tags.txt의 쉼표 형식은 유지.
