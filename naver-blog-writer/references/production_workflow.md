# 글 작성 후 이미지 프롬프트·HTML 제작 (Claude 환경)

이 문서는 새 블로그 콘텐츠의 전체 제작과 이미지·HTML 후속 요청에 사용한다. 제목·본문·이미지 프롬프트가 이미 있으면 대화의 최신 확정본을 이어받는다. 이미지는 사용자가 GPT Image 또는 나노바나나2로 직접 생성한다. 번호는 이미지 배치 순서이며 글 소제목 번호와 구분한다.

## 작업 폴더

```text
/home/claude/blog/<slug>/          ← 작업 폴더 (초안·중간 파일)
  post.md                          ← 최종 원고 (마크다운)
  prompts.md                       ← 이미지 프롬프트 3개 + 파일명 + 삽입 위치
  post-edit.html                   ← 편집용 (이미지 자리표시자 + 프롬프트 요약)
  post.html                        ← 이미지 연결용 (<img src="01-thumbnail.png"> 상대 경로)
  images/                          ← 비어 있음. 사용자가 생성한 이미지를 아래 이름으로 넣는 자리
    01-thumbnail.png  02-<section-slug>.png  03-<section-slug>.png
  tags.txt
/mnt/user-data/outputs/<slug>/     ← 전달용 복사본 + <slug>.zip
```

- 사용자 지정 저장 위치가 있으면 그것을 우선한다. 개인 경로나 예시 주제를 하드코딩하지 않는다.
- 파일 충돌 시 기존 결과를 덮어쓰지 말고 `<slug>-v2/`처럼 버전 폴더를 쓴다.
- 전달은 반드시 `present_files`로 한다. 우선순위: ZIP → prompts.md → 편집용 HTML 순으로 넘긴다.

## 이미지 프롬프트 — 최대 3개 (GPT Image · 나노바나나2 공용)

이 스킬은 이미지를 생성하지 않는다. 사용자가 GPT Image(ChatGPT/OpenAI) 또는 나노바나나2(Gemini 이미지)에 붙여넣을 프롬프트를 만든다. 연결된 이미지 MCP가 있어도 호출하지 않는다.

- **상한 3개**: `01-thumbnail` → `02-<slug>` → `03-<slug>`. 본문 이미지는 글에서 가장 시각화가 필요한 인용구/소제목 2곳을 골라 그 아래에 배치한다. 사용자가 더 적게 원하면 그 수를 따르고, 더 많이 요청하면 "이 스킬은 3장까지만 잡습니다"라고 알린 뒤 3개로 진행한다.
- **두 모델 공용 작성법**: 둘 다 자연어 문장을 잘 읽으므로 키워드 나열보다 **장면을 묘사하는 3~5문장**으로 쓴다. 순서는 `[피사체·행동] → [배경·소품] → [조명·색감] → [화풍·카메라] → [금지사항]`. 미드저니식 `--ar`, `--v` 파라미터는 쓰지 않고 비율은 문장으로 적는다(`16:9 landscape`).
- **필수 문구**(모든 프롬프트 끝): `16:9 landscape. No text, no letters, no logos, no watermark. No resemblance to any real person or celebrity.`
- **시리즈 스타일 한 줄**을 먼저 정해 세 프롬프트에 동일하게 넣는다(예: `soft warm natural light, navy and cream palette, clean editorial illustration style`). 업무 경험담에는 따뜻한 자연광과 네이비·크림을 기본 후보로 삼되 다른 주제나 사용자 지정 스타일에 강제하지 않는다.
- 썸네일은 모바일 목록에서 작게 보이므로 **피사체 하나, 배경 단순, 중앙 여백**(스마트에디터에서 제목 글자를 얹을 자리)을 지시한다.
- 한글 텍스트는 이미지 안에 넣지 않는다. 글자는 스마트에디터에서 얹는다.
- `prompts.md` 형식:

```text
## 시리즈 스타일
soft warm natural light, navy and cream palette, clean editorial illustration style

## 01-thumbnail.png — 삽입: 제목 바로 아래
(영어 프롬프트 3~5문장 + 필수 문구)
한글 설명: …

## 02-completion-gap.png — 삽입: 인용구 1 「…」 아래
…

## 03-review-role.png — 삽입: 인용구 4 「…」 아래
…
```

- 사용자가 생성 결과를 올리면 `view`로 열어 글자·얼굴·구성·실존 인물 재현 여부를 점검하고, 문제가 있으면 해당 프롬프트만 고쳐준다. 성공한 이미지의 프롬프트는 번호 변경이나 HTML 요청 때문에 다시 쓰지 않는다.

### 유명인 이슈의 가상 인물 이미지

- 유명인이 등장하는 기사에서는 실제 인물과 닮지 않은 가상 인물을 기본으로 사용하고, 기사의 핵심 상황·활동·감정을 장면에 반영한다. 유명인이라는 이유만으로 빈 장소나 소품만 반복하지 않는다. 가상 인물의 얼굴은 보여도 된다. 사용자가 인물 없는 이미지를 요청하면 그 선택을 따른다.
- 직업·활동·공간·행동처럼 이슈를 이해하는 데 필요한 맥락은 유지하되, 얼굴·헤어스타일·체형·고유 표식의 조합으로 당사자를 알아보게 만들지 않는다. 기사 사진이나 실제 인물 사진을 외모 참조로 사용하지 않는다.
- 각 이미지가 해당 소제목의 내용을 전달하도록 구체적인 행동·표정·장소·소품을 정한다. 예: 테니스 선수의 수술 후 복귀 기사 → 가상의 성인 여성 선수가 코트에서 자신감 있게 경기 준비를 하는 장면. 의료·신체 이슈에서도 신체 일부의 과장, 임의의 전후 비교, 확인되지 않은 결과를 그리지 않는다.
- 프롬프트에 `entirely fictional person, no resemblance to any real person or celebrity, conceptual editorial scene, not a documentary image`를 포함하고 가상 인물의 외모와 상황을 구체적으로 기술한다. 여러 장에서 같은 인물이 이어지면 가상 인물의 외형과 전체 화풍을 유지한다.
- 이미지 아래에 `AI 생성 이미지 · 기사 속 실제 인물과 무관한 가상의 인물입니다.`를 표시한다. HTML 2종에도 같은 설명을 유지하고, 실제 현장·인물의 기록으로 소개하지 않는다.
- 결과를 검토할 때 실존 인물의 재현 여부, 이슈·소제목과의 관련성, 가상 인물 표시를 확인한다. 가상 인물을 썼다는 이유만으로 법적 무침해를 보장하지 않는다.

## 파일 번호와 전달

썸네일부터 1로 시작하는 두 자리 번호를 사용한다. 최대 3장이므로 예:

```text
01-thumbnail.png
02-completion-gap.png
03-review-role.png
```

- 확장자는 `.png`를 기본으로 적고, 사용자가 다른 형식으로 저장하면 HTML의 경로만 바꾸도록 안내한다. 본문 파일명은 해당 섹션을 설명하는 영문 슬러그로 정한다.
- 번호·이름 변경 요청은 prompts.md·HTML 자리표시자·`<img>` 경로·ZIP 내부 안내를 함께 갱신한다.
- 최종 ZIP은 `cd /home/claude/blog && zip -r /mnt/user-data/outputs/<slug>.zip <slug>/`로 만들고 `unzip -l`로 파일 목록을 확인한다. `images/` 폴더는 빈 채로 넣고 README 한 줄(`생성한 이미지를 이 이름으로 저장하세요`)을 둔다.

## 읽기 편한 HTML

- 기존 모드·선택 제목·본문 내용을 보존한다. HTML 요청 때문에 제목 선정이나 글쓰기를 다시 시작하지 않는다. 디자인을 위해 사실·경험·통계·분량을 추가하지 않는다.
- 독립적으로 열리는 UTF-8 HTML 파일을 만든다. `lang="ko"`, viewport, 제목, 본문 구조를 제공하고 외부 폰트·스크립트 없이 읽히게 한다.
- 모바일 본문은 17~19px, 줄간격 1.8~2.0, 좌우 여백 20~24px를 기본으로 한다. 데스크톱은 본문 최대 폭 700~760px 정도로 제한한다. `word-break: keep-all`로 한국어 단어 단위 줄바꿈, 긴 파일명은 `overflow-wrap: anywhere`.
- 차분한 단색 배경, 명확한 제목 계층, 넉넉한 문단 여백. 핵심 문장만 강조하고 인용 박스와 체크리스트는 글 흐름에 필요한 위치에 둔다. 장식이나 중첩 카드로 본문을 압도하지 않는다.
- 핵심 본문 서식에는 인라인 CSS를 사용한다. 반응형 보완은 문서 스타일로 처리할 수 있으나 네이버 편집기에서 동일하게 유지된다고 보장하지 않는다. 본문 중간에 제작 설명·프롬프트·태그를 섞지 않는다. 본문 마지막에는 별도의 해시태그 영역을 둔다.

### 편집용 HTML과 이미지 연결용 HTML

- 전체 제작은 **편집용 `post-edit.html`**(눈에 보이는 이미지 자리표시자 + 예정 파일명 + 프롬프트 한 줄 요약)과 **이미지 연결용 `post.html`**(`<img src="images/01-thumbnail.png">` 상대 경로, 사용자가 같은 이름으로 저장하면 바로 보임) 두 가지를 제공한다. 특정 버전만 요청했으면 그 버전만 제공한다.
- 이미지가 아직 없으므로 "완성본"이라고 부르지 않는다. 이미지가 존재한다고 말하지 않는다.
- 사용자가 생성한 이미지 파일을 업로드해 "넣어줘"라고 하면 그때 base64로 내장한 완성본을 만든다.
- 기사 해설 이미지에는 `AI 생성 해설용 이미지`라고 표시한다. 인물·사업장과 혼동될 장면에는 실제 당사자의 사업장이나 상품을 촬영한 사진이 아니라는 설명을 붙인다. 기사 사진·영상 캡처를 재사용하지 않는다.

### 이미지 위치 표시

사용자가 삽입 자리를 요청하면 이미지 태그를 깨진 경로로 넣는 대신 눈에 보이는 자리표시자를 만든다.

- 제목·도입부 부근에 썸네일 자리, 선택한 두 섹션에 본문 이미지 자리를 둔다.
- 각 자리에 `이미지 01 · 썸네일`처럼 번호·용도, 장면 설명, 정확한 파일명을 표시한다. 예: `01-thumbnail.png`.
- 예정 파일명임을 표시하고 이미지가 존재한다고 말하지 않는다. 사용자가 업로드한 실제 이미지가 있을 때만 연결한다.

### 본문 끝 해시태그

- 두 HTML 모두 마지막 문단·FAQ·출처 뒤, article 내부 맨 마지막에 해시태그 8개를 넣는다. 형식은 `#권은비 #정예인 #의류사업`처럼 공백 구분이며, 모바일에서는 자연스럽게 줄바꿈한다. 태그 내용은 해당 글에서 선정한 목록을 사용한다.
- 작은 글자와 차분한 단색 배경으로 본문과 구분하되 읽기 쉬운 대비를 유지한다.
- 후속 태그 수정은 기존 영역을 갱신한다. 영역을 중복 추가하지 않는다. 별도 `tags.txt`는 `#` 없이 쉼표와 공백으로 구분한다.

### 검증과 전달

- 가능한 범위에서 HTML 구조를 점검한다(이미지 자리 수 = 프롬프트 수 ≤ 3, 파일명이 prompts.md와 일치, 해시태그 영역 1개). 브라우저 렌더링 확인이 불가능하면 그렇다고 밝힌다.
- 확인한 범위만 보고한다. 로컬 HTML 확인을 실제 네이버 편집기 검증이라고 부르지 않는다. 붙여넣기 절차는 [편집기 안내](editor_paste_guide.md)를 참고한다.
- 전체 ZIP에는 원고(post.md), prompts.md, HTML 2종, tags.txt, 빈 images/ 폴더를 포함한다. 수정 후 ZIP도 갱신하고 압축 내부 HTML이 최신 파일과 일치하는지 확인한다.
- 두 HTML의 출처, 가상 수치 안내, 이미지 캡션, 본문 끝 # 태그가 유지되는지 확인한다.
- `present_files`로 ZIP·prompts.md·편집용 HTML을 전달한다. "프롬프트를 GPT Image 또는 나노바나나2에 넣어 생성 → images/에 같은 이름으로 저장 → post.html 확인 → 스마트에디터에 옮기기" 순서를 짧게 안내한다. 자동 발행은 이 제작 요청에 포함되지 않는다.

## 태그 후속 요청

별도 태그 응답과 tags.txt의 기본은 `#` 없이 쉼표와 공백으로 나눈 한 줄이다. HTML 본문 끝의 `#` 포함 해시태그 영역과 구분한다. 태그만 요청하면 인사·설명·제목·코드블록 없이 태그만 반환한다. 이미 선정한 태그를 유지하고 형식만 바꾼다.

```text
AI업무자동화, 업무자동화, AI활용, 생성형AI, 업무생산성, 직장인AI, 자동화경험, 결과검증
```
