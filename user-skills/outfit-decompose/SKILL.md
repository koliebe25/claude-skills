# Outfit Decompose

착장 사진 → 아이템 분해 → 실사 제품컷 + 룩북 포스터.

이 스킬은 실제로 만들어 배포까지 마친 앱의 설계와, 그 과정에서 **실패한 뒤에야 알게 된 것들**을
담고 있습니다. 특히 이미지 생성 API에는 문서만 봐서는 알 수 없는 제약이 여러 개 있어,
모르고 시작하면 같은 곳에서 반드시 막힙니다.

## 이 앱이 하는 일

1. 전신 착장 사진 1장 업로드
2. 비전 모델이 아이템을 분해 (라벨·색 HEX·소재·핏·패턴 + 이미지 생성용 영문 묘사)
3. 사용자가 목록을 확인·수정 — **결과 품질을 바꿀 수 있는 유일한 손잡이**
4. 착용컷 1장 + 제품컷 N장 생성
5. 세로 9:16 / 정방 1:1 / 가로 16:9 포스터로 조립, PNG·JSON·CSV 내보내기

## 시작 전에 반드시 확인할 것

구현에 들어가기 전에 사용자에게 물어보세요. 나중에 뒤집히면 프롬프트를 통째로 다시 써야 합니다.

- **인물 화풍**: 실사인가, 3D 캐릭터인가? (광고용이면 실사)
- **얼굴 처리**: 초상권을 어떻게 다룰 것인가? (권장: 폰으로 얼굴 가린 미러 셀카 포즈)
- **제품컷 화풍**: 실사 플랫레이인가, 일러스트인가? (상세페이지용이면 실사)
- **헤어**: 헤어스타일 자체를 항목에 넣을 것인가? (상품이 아니면 빼고, 핀·모자만)

실제 개발에서 이 스펙이 **두 번 뒤집혔습니다**. 결과물을 보기 전에는 판단할 수 없는 종류라,
프롬프트를 한 파일에 격리해 두는 것이 그래서 중요합니다.

## 구현 순서

각 단계는 **눈으로 확인 가능한 결과**로 끝냅니다. 절반쯤 된 상태를 만들지 않습니다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | AI 없이 화면 3개 + 가짜 데이터 | 자리표시 이미지로 포스터가 조립되고 PNG 저장 |
| 2 | 착장 분석 (비전 모델) | 실제 사진에서 아이템 7~9개가 정확한 색·소재로 잡힘 |
| 3 | 이미지 생성 | 원본과 색·패턴이 일치하는 제품컷이 나옴 |
| 4 | 후처리 (배경/여백) | **흰 옷 사진에서도 옷이 지워지지 않음** |
| 5 | 내보내기 3비율 | 세로 1800×3200 PNG가 깨짐 없이 저장 |
| 6 | 비용 표시 · 오류 안내 | 키가 틀리면 "키가 유효하지 않습니다"로 나옴 |

**2단계를 3단계보다 먼저** 하세요. 분석은 이미지 생성보다 수십 배 싸서 빠르게 반복할 수 있습니다.
분석 결과가 부실한 채로 이미지를 뽑으면 돈만 쓰고 원인을 못 찾습니다.

## 구조

레이어를 나누는 기준은 **바뀌는 속도**입니다. 프롬프트는 매일 바뀌고 API 연결은 거의 안 바뀝니다.

```
src/
  app/
    api/analyze/    사진 → 구조화 JSON (비전)
    api/generate/   프롬프트 → 이미지
    page.tsx        업로드 → 편집 → 결과 3단계
  components/       UploadPanel · ItemEditor · PosterCanvas · ResultView
                    AttributePanel · KeySettings
  lib/
    prompts.ts      ← 품질의 90%. 한 파일에 모을 것
    providers.ts    Gemini / OpenAI 분기
    errors.ts       오류 해석 · 재시도 정책
    imageProcessing 배경 제거 · 여백 정리 (브라우저에서)
    pricing.ts      원화 비용 추정
    layout.ts       비율 프리셋
    store.ts        상태 (zustand 등)
    mock.ts         키 없을 때 데모 데이터
```

**브라우저에서 외부 AI를 직접 부르지 마세요.** 반드시 서버 라우트를 거쳐야 API 키가
개발자 도구에 노출되지 않습니다.

## 프롬프트 설계

이 앱은 **코드보다 프롬프트가 중요합니다.** 세 덩어리로 나눕니다.

| 상수 | 적용 | 역할 |
|---|---|---|
| `FRAME_RULES` | 공통 | 배경·구도·금지사항. 두 종류 컷의 톤을 맞춤 |
| `PORTRAIT_STYLE` | 착용컷 | 실사 인물 + 얼굴 가림 |
| `PRODUCT_STYLE` | 제품컷 | 이커머스 플랫레이 + **재해석 금지** |

전문은 `references/prompts.md`에 있습니다. 그대로 복사해 쓰고, 사용자 요구에 맞게 조정하세요.

### 효과가 컸던 세 가지

**금지를 구체적으로 씁니다.** "배경 없이"는 통하지 않습니다. 모델이 어떻게 실패하는지 본 뒤
그 실패를 이름으로 지목해야 합니다 — "체크무늬나 회색-흰색 격자를 절대 그리지 말 것.
그것은 편집 프로그램의 투명 표시일 뿐 배경이 아니다."

**실패의 결과를 알려줍니다.** "이 이미지는 실제 상품 광고에 사용된다"를 붙이면 모델이
재해석 금지 규칙을 훨씬 잘 지킵니다.

**복구법까지 씁니다.** "그래도 얼굴이 보인다면 폰을 더 크게 그려서 가릴 것" 처럼
모델이 스스로 판단해 고칠 여지를 줍니다.

  **3단계(이미지 생성)에 들어가기 전에 반드시 읽으세요.** 투명 배경·흰 옷·429 오류가 여기 있습니다.
- **`references/prompts.md`** — 분석/착용컷/제품컷 프롬프트 전문. 2·3단계에서 사용.

## 비용을 반드시 노출할 것

AI 앱은 **버튼 하나가 돈**입니다. 돈이 드는 지점마다 예상 비용을 원화로 보여주세요.

- 업로드 화면 → 분석 비용
- 화질 토글 → 컷당 단가
- 생성 버튼 → 착용컷·제품컷 나눈 내역 + 합계 + 다른 화질로 바꿨을 때 금액
- 결과 화면 → 실제로 성공한 컷 기준 사용 비용
- 재생성 버튼 → 컷당 추가 비용

포스터 한 장이 아이템 8개 기준 **₩850~2,800**입니다. 사용자가 모르고 누르면 안 되는 금액입니다.

## 공개 배포할 때

배포 주소는 누구나 접속합니다. 서버에 개발자의 API 키를 넣으면 **주소를 아는 사람이
남의 돈을 씁니다.** 기본값으로 다음 구조를 권하세요.

- 서버에 키를 넣지 않고 배포 → 방문자는 **데모 모드**로 전체 흐름 체험
- 실제 생성은 방문자가 **설정에서 본인 키**를 입력 (그 브라우저 탭에만 보관, 서버 저장 없음)

키를 넣어야만 한다면 배포 전에 콘솔에서 **월 지출 한도**를 낮게 걸도록 안내하세요.

## 완료 전 검수

```
기능
□ 키 없이 접속해도 데모 모드로 전체 흐름이 완주되는가
□ 잘못된 키를 넣으면 사람이 읽을 수 있는 안내가 뜨는가
□ 생성 실패 후에도 버튼이 복구되어 앱을 계속 쓸 수 있는가
□ 새로고침해도 오류 없이 뜨는가

품질
□ 착용컷에 얼굴이 조금이라도 보이지 않는가
□ 흰 옷 사진에서 옷이 배경과 함께 지워지지 않는가
□ 제품컷에 원본에 없는 포켓·단추·프린트가 추가되지 않았는가
□ 배경에 체크무늬·그림자·바닥이 없는가

안전
□ API 키가 저장소에 올라가지 않았는가 (.gitignore 확인)
□ 예시 설정 파일에 실제 키가 남아 있지 않은가
□ 공개 배포 시 서버에 키를 넣지 않았는가
```

품질 항목은 **눈으로 보고** 확인하세요. 생성된 이미지를 실제로 열어봐야 합니다.
코드가 통과했다고 결과가 맞는 것이 아닙니다.

## 작업 태도

**추측 대신 측정하세요.** "흰 옷이 지워질 것 같다"는 걱정은 실제 픽셀을 세어 확인할 수
있습니다. 확인 없이 고치면 없던 문제를 만들어냅니다.

**생성 결과를 직접 보세요.** 이 앱의 버그는 대부분 코드가 아니라 이미지에 있습니다.
체크무늬가 깔린 것도, 라벨이 서술형으로 나온 것도, 헤어 패널이 누락된 것도
결과물을 열어보고서야 알았습니다.

**실패를 사용자 언어로 번역하세요.** `429 RESOURCE_EXHAUSTED`는 개발자에게도 불친절합니다.
"월 지출 한도를 초과했습니다. 기다린다고 풀리지 않습니다"까지 써줘야 다음 행동을 할 수 있습니다.
